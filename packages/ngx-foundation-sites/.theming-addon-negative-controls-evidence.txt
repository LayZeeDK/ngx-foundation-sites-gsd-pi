3. Add a static `import 'sass'` to preview.ts
--------------------------------------------------------------------------
Mutation: packages/ngx-foundation-sites/.storybook/preview.ts
  added `import 'sass';` as the first line.

Finding: the T03 verify-theming-bundle gate, as committed, did NOT catch
this. The build's entrypoint size jumped from 2.09 MiB to 6.04 MiB (sass's
compiler was pulled into a statically-imported preview chunk,
855.<hash>.iframe.bundle.js, confirmed to contain sass's own
`compileStringAsync` export and to be a static `import` target of
iframe.html's module script) -- but SOURCES_MARKER
($button-background-hover-lightness, this project's own scss text) never
appears in sass's compiled output, so the existing marker-based check
passed vacuously. This is a real gap in the D034 lazy-loading guarantee as
gated by T03.

Fix applied (in scope for this task, since a negative control that cannot
go red is not a negative control): added a second guard to
verify-theming-bundle.mjs, symmetric to the SOURCES_MARKER check --
SASS_PACKAGE_MARKER = 'compileStringAsync' (part of `sass`'s public API,
never called by theming-worker.ts, which only calls the sync
`compileString`). Asserts presence in at least one emitted file (positive
control) and absence from iframe.html's own static import list.

RED (after adding the guard, with the mutation still applied):
  $ nx run ngx-foundation-sites:verify-theming-bundle
  Theming bundle verification FAILED:
    855.7723cd7b.iframe.bundle.js (bundles the `sass` package itself) is
    imported directly by iframe.html
      likely cause: something outside theming-worker.ts (e.g. a stray
      `import 'sass'` in .storybook/preview.ts) statically imports the
      `sass` package, pulling its ~800 KiB payload into preview boot
      instead of behind the lazy `new Worker(new URL(...))` split (D034).
  EXIT_VERIFY=1

Revert: `import 'sass';` removed from preview.ts.

GREEN:
  $ nx run ngx-foundation-sites:verify-theming-bundle
  Theming bundle verification PASSED:
    addon manager bundle content-matches `nfs/theming` exactly once and is
    imported by index.html
    sources marker `$button-background-hover-lightness` is present but
    absent from iframe.html's own import list (preview boot stays lazy)
    `sass` package marker `compileStringAsync` is present but absent from
    iframe.html's own import list (sass payload stays out of preview boot)
    Worker split, #nfs-theming injection target, and the R026-exempted
    injection file are all present
  EXIT_VERIFY=0
